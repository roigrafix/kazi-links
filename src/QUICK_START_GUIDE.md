# Message Central OTP Refactor - Quick Start Guide

## 🚀 Get Started in 3 Steps

### Step 1: Add Secrets to Wix (5 minutes)

1. Go to **Wix Dashboard** → **Develop** → **Secrets Manager**
2. Click **Add Secret** and add these three secrets:

```
MC_CUSTOMER_ID = [Your Message Central Customer ID]
MC_PASSWORD = [Your Message Central Password]
MC_EMAIL = [Your Message Central Email]
```

3. Click **Save** for each secret

### Step 2: Deploy Code (Already Done ✅)

The backend code has been refactored and is ready to deploy:
- ✅ `/src/backend/messageCentral.jsw` - Refactored to use Message Central API
- ✅ `/src/backend/http-functions/verifyOTP.js` - Updated to accept verificationId
- ✅ Frontend already compatible - No changes needed

### Step 3: Test the Integration (10 minutes)

**Test Send OTP:**
```bash
curl -X POST http://localhost:3000/_functions/sendOTP \
  -H "Content-Type: application/json" \
  -d '{"phoneNumber": "+919876543210"}'
```

**Expected Response:**
```json
{
  "success": true,
  "data": {
    "verificationId": "vid_..."
  }
}
```

**Test Verify OTP:**
```bash
curl -X POST http://localhost:3000/_functions/verifyOTP \
  -H "Content-Type: application/json" \
  -d '{
    "phoneNumber": "+919876543210",
    "code": "123456",
    "verificationId": "vid_..."
  }'
```

**Expected Response:**
```json
{
  "success": true,
  "valid": true,
  "message": "Phone number verified successfully"
}
```

## 📊 Complete Flow

```
1. User enters phone number
   ↓
2. Frontend calls sendOTP()
   ↓
3. Backend calls Message Central API
   ↓
4. Message Central returns verificationId
   ↓
5. Frontend stores verificationId
   ↓
6. User enters OTP code
   ↓
7. Frontend calls verifyOTP(phone, code, verificationId)
   ↓
8. Backend calls Message Central API with verificationId
   ↓
9. Message Central validates OTP
   ↓
10. Backend updates Wix CRM
    ↓
11. User is verified ✅
```

```

✓ Check MC account is active
✓ Verify OTP service is enabled
✓ Check phone number format (+91...)
```

```
✓ Ensure frontend is storing verification ID
✓ Check verification ID is passed to verify endpoint
✓ Verify MC API is returning verificationId
```

## 🎯 Key Points

### Verification ID
- Unique identifier for each OTP request
- Generated by Message Central
- Must be passed to verify endpoint
- New ID generated on resend
- Prevents OTP reuse

### Phone Number Format
- Accepts any format (10-digit, with country code, etc.)
- Automatically formatted to E.164 (+91...)
- Example: +919876543210

### CRM Integration
- Contact created on first verification
- Contact updated on subsequent verifications
- Phone verification status stored
- Verification timestamp recorded

## 🎓 Key Learnings

### Verification ID Flow
- Each OTP request gets unique verification ID from MC
- Verification ID must be passed to verify endpoint
- Prevents OTP reuse across different sessions
- New ID generated on resend

### Credential Management
- Credentials cached for 1 hour
- Automatic refresh on cache expiry
- Reduces Wix Secrets Manager API calls
- Improves performance

### CRM Integration
- Contact creation/update on successful verification
- Phone verification status stored in CRM
- Graceful error handling if CRM update fails
- OTP verification still succeeds even if CRM fails
